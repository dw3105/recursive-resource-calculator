## What to build

**Quality survives both directions.** Supply AND drain carry item quality, and quality stays in the
measurement keys, so two qualities of one item can never collapse into one total. Add the legendary supply
regression and its matching drain regression BEFORE changing the adapter.

**Capacity is derived, not assumed.** Perimeter devices are legally placed, powered, and carry the declared
load with measured headroom. Include the incident's high-load external item endpoint, not only a low-rate
single-item example.

**Controls are independent.** Hand-built working references are pinned by blueprint bytes and are NEVER
generated by the code under test: item conversion, fluid-to-item conversion, and non-normal-quality item
transfer, each with independently derived expected rates. A deliberate internal disconnection, a missing
recipe and a wrong quality each FAIL.

**Harness failure is its own verdict.** A setup, placement or capacity failure is reported separately from a
factory failure, with its own code. A failed run must never be reported as a product regression when the
harness is what broke.

**Fixture power never repairs a factory.** Harness-only power can never cover a generated factory's unpowered
consumer. A deliberately unpowered consumer is the negative control.

**Emit the bindings.** Every observation carries `prepared_input_sha256`, `config_sha256` and
`harness_qualification_id`, derived from the input actually submitted to the run, never added afterwards.

**Deliver a runnable handoff** in `docs/tasks/114_qualification.md`: control blueprint strings, warm-up and
sampling windows, expected rate per output and per quality, discrete-count tolerance, timeouts, diagnostics,
and the exact commands the user runs in game.
