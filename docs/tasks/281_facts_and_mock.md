## Explain very simply

Our fixtures, our python/lua constants and our mock game (`tests/harness.lua`) all carry facts about Factorio
(machine sizes, underground reach, beacon range, inserter offsets, which members a LuaObject has). Nobody checked
them against the real game. This lane turns every such fact into a plain data row. Later the integrator loads the
rows inside real headless Factorio and compares each one with the live game. You write the extractors and the rows;
you never write engine code.

## What to build

1. `tools/fixture_facts.lua` (run: `lua5.2 tools/fixture_facts.lua`): for every row of `tests/fixtures/INDEX.tsv`
   with class `catalog`, load the file (JSON through `helpers.json_to_table` after `require "tests.harness"` +
   `H.new_world()`; `.lua` fixtures with `dofile`), find its catalog (top-level `catalog`, or `candidate.catalog`,
   or `prototypes` for `tests/export_golden/*.json`; `tests/fixtures/engine/roboport-cell.json` → its `measured`
   block), and emit one row per LEAF value under the catalog: `profile \t path \t value \t fixtures` where `path` is
   the dotted key path (`entity.beacon.supply_area_distance`, `recipe.iron-gear-wheel.energy`, array index as a
   number), `value` = JSON of the leaf, `fixtures` = comma list of every fixture carrying that same (profile, path,
   value). Write `tests/fixtures/engine_facts/catalog_facts.tsv`, sorted, deterministic. Also write
   `tests/fixtures/engine_facts/catalog_conflicts.tsv`: every (profile, path) where two fixtures disagree.
2. `tests/fixtures/engine_facts/constants.json` (hand-written, one object per constant): `{"file": ..., "line": N,
   "name": ..., "value": ..., "probe": {"kind": "entity"|"item"|"recipe"|"force", "name": <prototype name or null>,
   "field": <LuaXPrototype attribute or method name>, "arg": <optional>, "expect": "equal"|"tile_size"|...}}`.
